## 1 big thing: Qwen3.6-27B and Coder-Next trade punches, dense wins on friction

Qwen3.6-27B (dense, Apache 2.0) and Qwen3-Coder-Next (80B/3B MoE) both clear Claude 4.5 Opus on SWE-bench. A 20-hour head-to-head on RTX PRO 6000 Blackwells found no winner — they hit and miss on different task types.

**Why it matters:** For local coding agents on your own GPU, the 27B dense model is the lower-friction pick — half the VRAM, higher SWE-bench (77.2% vs 71.3%). The local open-weight tier has arrived for side-project work.

**Yes, but:** Informal Reddit benchmark — quant, hardware, and task mix shift the winner.

**Be smart:** Under 48GB VRAM? Start with Qwen3.6-27B at Q5_K_M via Ollama.

## OpenCode + local Qwen3 is a working unlimited-token Claude Code alternative

OpenCode integrates with llama.cpp and Ollama via one config. A developer ran Qwen3-27B at Q5_K_P, 128K context, and called it competitive with cloud tools — right as providers started throttling heavy users mid-session.

**Why it matters:** Fixed hardware cost, unlimited daily tokens, no "out of credits" mid-task. For scrappy side-app builds, this removes the worst failure mode of cloud coding agents this quarter.

**Yes, but:** 24GB+ VRAM or unified-memory Mac required. Tool calls need llama.cpp's `--jinja` flag. Not zero-friction.

## CLAUDE.md ends the 20-minute Claude Code re-onboarding ritual

Coding preferences, project layout, and behavioral rules in a `CLAUDE.md` at the project root load each session and apply to spawned agents.

**Why it matters:** Highest-ROI setup change for daily Claude Code users. Twenty minutes of re-explaining recovers inside a week, and behavior stays consistent when building incrementally.
